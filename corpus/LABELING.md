# 正解ラベルの付け方

`corpus/labels/pNN.json` は、`corpus/reports/pNN.json` の各単位（`units`）に、どのJevルールが当たるかを付けたもの。LLMのサブエージェントが、報告全文を読んで付けた。静的ルール（`detector: static`）には付けない。

現在のラベルは、コミット eabe402 の時点で、下の指示で付けたものである。対象はJevルール35本（`long-sentence` を除く）。

## サブエージェントに渡した指示

### 単位の種類

- 「#」で始まる unit は heading（見出し）
- 「- 」「* 」「+ 」「数字. 」で始まる unit は list-item（箇条書きの1項目）
- それ以外は sentence（文）

ルールの `subject` に含まれない種類の unit には、そのルールを付けない。

### 判定のしかた

各 unit について、ルールそれぞれを次の手順で判定する。

1. その unit が「該当の記述」（`rule.yml` の `applies`）に当たるかを判断する。当たらなければ、そのルールは付けない。
2. 当たる場合、「除外の記述」（`excludes`）があれば、それに当たるかを判断する。当たれば、そのルールは付けない。
3. 該当の記述に当たり、除外の記述に当たらないときだけ、そのルールを付ける。

守ること。

- 判断の根拠は、ルールの「該当の記述」と「除外の記述」だけにする。記述に書かれていない条件を自分で足さない。記述を広げて解釈しない。
- 記述から該当と言い切れないときは、付けない。
- 必ず報告全文を読み、その unit の前後の文と、報告の中での位置を踏まえて判断する。
- 判断にスクリプトや正規表現を使わない。自分で読んで判断する。

### investigation についてだけ添えた判断例

リポジトリの持ち主が示した判断である。READMEの原文には書かれていない。

- 「本番環境での動作は未確認です。」→ 付ける
- 「権限がなかったため未実施です。」→ 付けない（除外の記述に当たる）
- 「〜はずです」「〜の可能性があります」のように推量で述べる文は、未確定の表現に当たる → 付ける（除外の記述に当たる場合を除く）

## 形式

```json
{
  "id": "p01",
  "labels": [
    {"unit": 0, "rules": []},
    {"unit": 1, "rules": ["investigation"], "reasons": {"investigation": "「未確認です」。調べた記述がない"}}
  ]
}
```

- `labels` は `units` と同じ長さで、`unit` は `units` の添字（0始まり）。
- `reasons` は、付けたルールごとに、根拠になった語句と理由。

## 分かっている問題

- 担当したサブエージェントによって、判断の幅が違う。`stance-ending` は、1人が箇条書きの常体を10個該当にし、ほかの担当はほぼ付けていない。
- 1つの報告を1人しか見ていない。付け漏れや付けすぎを確かめる2人目がいない。
